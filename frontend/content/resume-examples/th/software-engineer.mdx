## อะไรทำให้เรซูเม่วิศวกรซอฟต์แวร์โดดเด่นในตลาดงานไทย

อุตสาหกรรมเทคโนโลยีไทยเติบโตเร็วที่สุดในอาเซียน ขับเคลื่อนโดยบริษัทชั้นนำอย่าง **Agoda** (engineering hub ระดับโลก 1,000+ devs), **KBTG** (Kasikorn Business Technology Group — fintech arm ของ KBank), **LINE MAN Wongnai** (super app ด้าน food delivery), **SCBX/SCB 10X** (digital banking), **True Digital** และ **AIS** นโยบาย Thailand 4.0 และ BOI Digital Promotion ทำให้ตลาดงาน dev ในกรุงเทพฯ แข่งขันสูงและเงินเดือนพุ่งเร็ว เอกสารนี้ — หรือที่เรียกว่าประวัติย่อหรือเรซูเม่ (resume) — เป็นเครื่องมือสำคัญที่สุดในการได้รับโอกาสสัมภาษณ์งานในสาขา วิศวกรซอฟต์แวร์

เรซูเม่วิศวกรซอฟต์แวร์ในไทยต่างจากสาขาอื่นตรงที่ **tech stack ต้องเห็นชัดภายใน 3 วินาที** — recruiter ที่ Agoda จะ filter ด้วยคำว่า "Go", "Kotlin", "Kubernetes" ก่อนอ่านรายละเอียดใดๆ ขณะเดียวกัน engineering manager ต้องการเห็น **system impact** ไม่ใช่แค่ list ภาษาที่ใช้ "Built real-time pricing engine handling 50K req/sec" ทรงพลังกว่า "Proficient in Go, Python, Kafka" หลายเท่า

## ตัวอย่างสรุปประสบการณ์มืออาชีพ

### ระดับจบใหม่ / Junior Developer

Backend developer จบ Computer Engineering จาก KMITL มีประสบการณ์ฝึกงาน 4 เดือนที่ KBTG ในทีม Payment Gateway (Kotlin + Spring Boot) พัฒนา API endpoint 8 ตัวที่ serve 2K transactions/day ผ่าน 100% unit test coverage มี personal projects 3 ตัวบน GitHub (React + Go) ได้รางวัลชนะเลิศ Hackathon Junction Asia 2025

### ระดับกลาง (3-5 ปี)

Full-stack engineer ประสบการณ์ 4 ปี ปัจจุบันอยู่ทีม Search & Discovery ที่ LINE MAN Wongnai พัฒนา restaurant recommendation engine ด้วย Go + Elasticsearch ที่ serve 15M searches/day ลด search latency จาก 200ms เป็น 45ms (P95) Refactor legacy monolith เป็น 6 microservices บน GKE ลด deployment time จาก 2 ชม. เหลือ 15 นาที มีประสบการณ์ Python (FastAPI), TypeScript (Next.js), PostgreSQL, Redis และ Kafka

### ระดับอาวุโส / Tech Lead

Senior Software Engineer / Tech Lead ประสบการณ์ 8 ปี ปัจจุบันนำทีม 7 คนในแผนก Pricing Platform ที่ Agoda ออกแบบ real-time pricing system ที่ process 500K events/sec ด้วย Go + Kafka + ClickHouse ลดต้นทุน cloud infrastructure 35% ($2.1M/year) ด้วยการ optimize Kubernetes resource allocation นำเสนอ architecture review สำหรับ cross-team projects 3 ครั้ง/ไตรมาส เคย lead migration จาก monolith สู่ microservices ที่ SCBX (12 services, 0% downtime) ก่อนย้ายมา Agoda

## ทักษะสำคัญที่ควรระบุ

### Programming Languages & Frameworks
- **Go** — ภาษาหลักที่ Agoda, LINE MAN Wongnai, SCBX ใช้สำหรับ backend services ที่ต้อง high performance ถ้ามีประสบการณ์ Go ในตลาดไทย = เงินเดือนสูงกว่า average 20-30%
- **Python (FastAPI/Django)** — หลากหลายใช้ทั้ง backend, data engineering, ML ได้เปรียบในตำแหน่งที่ต้องทำ data pipeline หรือ AI features
- **Kotlin / Java (Spring Boot)** — มาตรฐานในธนาคารและ fintech (KBTG, Ascend, 2C2P) ทุกธนาคารในไทยยังรัน Java-based core banking
- **TypeScript / React / Next.js** — frontend stack หลักในตลาดไทย Vue.js ยังมีใช้ (Shopee TH, บางทีม LINE) แต่ React dominant

### Cloud & Infrastructure
- **AWS / GCP** — Agoda ใช้ GCP, KBTG ใช้ hybrid (on-prem + AWS), LINE ใช้ Verda (private cloud) + GCP ระบุ specific services: EKS, Lambda, CloudFront ไม่ใช่แค่ "AWS"
- **Docker / Kubernetes** — required สำหรับ mid+ level ที่ทุกบริษัทเทค บริษัทไทยขนาดกลางอาจยังใช้ Docker Compose
- **CI/CD (GitHub Actions, GitLab CI, Jenkins)** — ระบุ pipeline ที่เคยสร้าง: "GitHub Actions pipeline deploying to EKS, 15-min cycle"

### System Design & Practices
- **Microservices Architecture** — ออกแบบ service boundaries, inter-service communication (gRPC, Kafka, REST)
- **Database (PostgreSQL, MongoDB, Redis)** — ระบุ scale: "PostgreSQL 500GB+ with read replicas" ไม่ใช่แค่ "SQL"
- **Monitoring (Datadog, Grafana, PagerDuty)** — senior level ต้องแสดงว่าดูแล production system ได้ SLA/SLO experience

## ผลงานเชิงตัวเลขที่น่าสนใจ

ใช้ pattern: built [what] → achieved [metric] → using [tech] ทุก bullet ต้องมีตัวเลข:

- ออกแบบ real-time notification service ที่ส่ง 2M push notifications/day ด้วย Go + Firebase Cloud Messaging ลด delivery latency จาก 5 วินาทีเหลือ 800ms ที่ LINE MAN Wongnai
- Refactor search API จาก monolith Ruby สู่ Go microservice ลด response time จาก 350ms เป็น 45ms (P99) รองรับ traffic เพิ่มจาก 5K เป็น 25K req/sec โดยไม่เพิ่ม server
- พัฒนา automated testing pipeline ด้วย GitHub Actions ลดเวลา CI/CD cycle จาก 45 นาทีเหลือ 12 นาที ครอบคลุม 85% code coverage สำหรับ 3 microservices
- สร้าง internal developer tool (React + FastAPI) ที่ช่วยทีม 25 คนจัดการ feature flags ลดเวลา config change จาก 30 นาที (manual deployment) เหลือ 2 นาที (UI toggle)
- นำทีม 5 คน migrate legacy payment system จาก PHP สู่ Kotlin (Spring Boot) ภายใน 6 เดือน ไม่มี downtime ประมวลผลธุรกรรม 50K/day มูลค่ารวม 80 ล้านบาท/เดือน
- ลดค่า cloud infrastructure 28% (ประหยัด 1.5 ล้านบาท/เดือน) โดย optimize Kubernetes pod autoscaling และ implement spot instances สำหรับ non-critical workloads บน AWS

## เคล็ดลับรูปแบบและเทมเพลตเรซูเม่วิศวกรซอฟต์แวร์

1. **แยก "Technical Skills" ชัดเจนจาก Work Experience** — Engineering manager ที่ KBTG หรือ Agoda ต้องเห็น tech stack ภายใน 3 วินาที จัดกลุ่มตาม domain: Languages / Frameworks / Cloud & Infra / Databases / Tools ไม่ใช่ list ยาวไม่จัดหมวด

2. **ใส่ system scale ในทุก bullet** — "Built an API" ไม่พอ → "Built REST API serving 15K req/sec across 4 microservices on GKE" ระบุ requests/sec, data size, user count หรือ SLA target ทุก technical bullet

3. **Link GitHub / Portfolio ใน header** — วางข้าง email และเบอร์โทร ถ้า best work อยู่ใน private repo ให้อธิบายใน "Key Projects" section: architecture, tech stack, scale, outcome บริษัทเทคในไทยดู GitHub contribution graph เป็น signal เสริม

4. **1 หน้าสำหรับ <5 ปี, 2 หน้าสำหรับ senior** — ไม่เกิน 2 หน้าแม้แต่ Staff Engineer ข้อมูลเก่ากว่า 5 ปีสรุปใน 1-2 บรรทัด อย่าเสียพื้นที่กับ internship ถ้ามี full-time experience แล้ว

5. **ใช้ภาษาอังกฤษ** — แม้สมัครบริษัทไทย เรซูเม่ dev ควรเขียนอังกฤษ เพราะ code, documentation, Jira tickets ล้วนใช้อังกฤษ ข้อยกเว้น: บริษัทไทยขนาดเล็กที่ลงประกาศภาษาไทยบน JobThai

6. **ไม่ต้อง objective statement** — แทนที่ด้วย 2 บรรทัด summary: tech stack + years + biggest technical achievement "Senior Go engineer, 6 years, led migration serving 500K daily users at SCBX"

## เคล็ดลับจากผู้จัดการฝ่าย Engineering ในประเทศไทย

> **เรซูเม่ dev ที่ได้สัมภาษณ์นำด้วย system impact ไม่ใช่ language list**

ในฐานะ Engineering Manager ที่ KBTG ที่ review เรซูเม่ dev 50+ ฉบับต่อเดือน pattern ชัดเจน: คนที่เขียน "Built real-time transaction monitoring system processing 100K events/sec using Go and Kafka" ได้ callback คนที่เขียน "Proficient in Go, Java, Python, Kafka, Redis" ถูก filter ออก

สิ่งที่ผมดูหลังจาก tech stack: **(1)** ขนาดระบบที่เคยดูแล — 1K req/sec ต่างจาก 100K req/sec **(2)** บทบาทใน team — individual contributor หรือ lead การออกแบบ **(3)** production ownership — on-call, incident response, SLA ถ้าคุณ "own" production system ที่มี real users ให้เขียนชัดเจน มันแยก senior จาก mid-level ได้ทันที

เรื่อง job-hopping ในสาย dev ไทย: 1.5-2 ปีต่อที่ถือว่าปกติ ไม่เหมือนสายอื่นที่คาดหวัง 3-5 ปี แต่ถ้าออกก่อน 1 ปีติดกัน 2 ที่ จะถูกตั้งคำถาม

## คำถามสัมภาษณ์ที่พบบ่อยสำหรับวิศวกรซอฟต์แวร์ในประเทศไทย

### อธิบายระบบที่คุณออกแบบที่ต้องรองรับ scale สูง — trade-offs ที่เลือกคืออะไร?

คำถาม system design ที่ Agoda, KBTG, LINE ถามทุกรอบ senior สำหรับ mid-level อาจถามง่ายกว่า: "ออกแบบ URL shortener" หรือ "ออกแบบ chat system" อธิบาย architecture decisions ว่าทำไมเลือก tech นั้น: "เลือก Kafka over RabbitMQ เพราะ throughput 100K msg/sec + message replay" ระบุ scale (req/sec, data volume) และ constraints ที่ drive decision

### เล่าเกี่ยวกับ production incident ที่คุณ debug — กระบวนการคุณเป็นอย่างไร?

คำถามวัด production ownership อธิบาย: symptoms → diagnostic steps (logs, metrics, traces) → root cause → fix → post-mortem ตัวอย่าง: "Database connection pool exhausted ที่ KBTG ตี 2 — ดู Datadog metrics เห็น connection count spike → พบ long-running query ใน slow query log → optimize query + add connection timeout → สร้าง alert rule ป้องกัน" แสดง monitoring tools ที่ใช้

### Tech stack ปัจจุบันของคุณคืออะไร? ถ้าต้องเลือก stack ใหม่จะเลือกอะไร?

คำถามวัดว่าคุณเลือก technology อย่าง informed ไม่ใช่แค่ "ใช้เพราะ senior เลือก" ตอบ: tech ปัจจุบัน + เหตุผลที่เลือก + trade-offs ที่รู้ + อะไรจะเปลี่ยนถ้าเริ่มใหม่ ตัวอย่าง: "ใช้ REST + PostgreSQL แต่ถ้าเริ่มใหม่จะเลือก gRPC เพราะ internal services ไม่ต้องการ human-readable format และ protobuf เร็วกว่า 3x"

### เงินเดือนที่คาดหวังเท่าไหร่?

ศึกษา range จาก Glassdoor + Blognone salary survey ก่อนสัมภาษณ์ ตอบเป็นช่วง: "70,000-90,000 บาท/เดือน ตามประสบการณ์ 4 ปีในสาย Go backend" ถ้าสมัคร Agoda/LINE ที่เงินเดือนสูงกว่าตลาด ให้ raise range ขึ้น 20-30% จากค่าเฉลี่ย ถามเรื่อง total package: stock options, RSU, education budget, remote policy

### Code review process ของคุณเป็นอย่างไร? ดูอะไรบ้าง?

คำถามวัดทั้ง technical depth และ collaboration ตอบ: correctness, readability, test coverage, performance implications, security กล่าวถึงวิธี give/receive feedback — "ผมใช้ 'suggestion' comments ใน GitLab MR แทน 'mandatory change' เพื่อให้ author ตัดสินใจ" แสดงว่าคุณ balance quality กับ velocity ได้

## ข้อผิดพลาดที่ควรหลีกเลี่ยง

### 1. List ภาษาโปรแกรมทุกตัวที่เคยแตะ

"Python, Java, Go, Ruby, PHP, C#, JavaScript, TypeScript, Rust, Dart, Swift" ไม่ช่วยอะไร — recruiter ไม่รู้ว่าคุณเก่งอะไรจริง เลือก 3-4 ตัวที่เชี่ยวชาญจริง + ระบุ context: "Go (primary, 3 years, production microservices), Python (secondary, data pipelines)"

### 2. ไม่ระบุ system scale

"พัฒนา REST API" vs "พัฒนา REST API serving 25K req/sec, 99.9% uptime, handling 5TB data/month" — ข้อแรกถูก filter ออกทันที ทุก bullet ต้องมี scale metric: requests, users, data size, latency

### 3. ใส่ coursera certificates แทน production experience

Recruiter ที่ Agoda หรือ KBTG ไม่นับ Coursera/Udemy certificates เป็นประสบการณ์จริง ใส่ได้ถ้าเป็น AWS Certified Solutions Architect หรือ GCP Professional Cloud Architect แต่ "Python for Beginners" Certificate ไม่ช่วย — เอาพื้นที่ไปเขียน projects ดีกว่า

### 4. เขียน responsibilities แทน impact

"Responsible for developing backend features" → "Developed payment processing module handling 50K daily transactions, reducing failed payments from 3.2% to 0.8% (saving 1.2M THB/month in lost revenue)" ทุก bullet ต้อง answer: "So what? What changed because of your work?"

### 5. ไม่ปรับเรซูเม่ตาม job description

สมัคร backend position ที่ Agoda (Go + microservices) ด้วยเรซูเม่ที่เน้น frontend React experience = ถูก filter ออก ปรับ summary, skills order และ bullet points ให้ match กับ JD ทุกครั้ง เวลา 15 นาทีที่ลงทุนปรับ = ROI สูงที่สุดในการหางาน

## การปรับแต่งเรซูเม่วิศวกรซอฟต์แวร์สำหรับระบบ ATS

ไม่ว่าจะเรียกว่าประวัติย่อ เรซูเม่ หรือ curriculum vitae การปรับแต่งสำหรับระบบ ATS ล้วนยึดหลักการพื้นฐานเดียวกัน บริษัทเทคในไทย ส่วนใหญ่ใช้ ATS: Agoda ใช้ Greenhouse, KBTG ใช้ Workday, LINE ใช้ Lever หรือ internal system วิธีผ่าน ATS:

- **ใช้ชื่อ technology ตรงๆ** — "React.js" ไม่ใช่ "front-end library" / "Kubernetes" ไม่ใช่ "container orchestration" ATS match exact keywords
- **ใส่ทั้ง abbreviated และ full form** — "Amazon Web Services (AWS)", "Continuous Integration/Continuous Deployment (CI/CD)", "Google Kubernetes Engine (GKE)"
- **ใช้ section headers มาตรฐาน** — "Work Experience", "Technical Skills", "Education", "Projects" ไม่ใช่ headers ครีเอทีฟที่ ATS อาจไม่เข้าใจ
- **วาง tech stack ไว้ 3 ที่** — Skills section (primary), Summary (top 3-4), Work Experience bullets (ในบริบท) ATS ให้ weight กับ keyword frequency
- **ไม่ใช้ตาราง columns หรือ graphics** — single column, plain text, standard fonts ATS ของ Greenhouse อ่าน 2-column layout ไม่ถูก
- **บันทึกเป็น PDF** — ทุก platform ในไทย (JobThai, JobsDB, LinkedIn, Greenhouse) support PDF ดีที่สุด
