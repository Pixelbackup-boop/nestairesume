## ITエンジニアの履歴書は特殊

ITエンジニアの履歴書・職務経歴書は、他の職種とは異なる独自の要素が求められます。技術スキルの詳細なリスト、プロジェクト単位の実績記載、GitHubやポートフォリオへのリンクなど、**技術力を具体的に示す情報**が重要です。

---

## 技術スキルの記載方法

### カテゴリ分けが鉄則

技術スキルは必ずカテゴリ分けして記載します。

**言語：** Python, TypeScript, Go, Java, SQL
**フロントエンド：** React, Next.js, Vue.js, Tailwind CSS
**バックエンド：** Node.js, FastAPI, Spring Boot
**インフラ：** AWS (EC2, S3, Lambda, RDS, ECS), Docker, Kubernetes
**DB：** PostgreSQL, MySQL, Redis, MongoDB
**CI/CD：** GitHub Actions, CircleCI, ArgoCD
**その他：** Agile/Scrum, テスト駆動開発, コードレビュー

### 経験年数の記載

各技術の経験年数や習熟度を記載すると、スキルの深さが伝わります。
- Python — 5年（設計・レビュー可能）
- React — 3年（プロダクション運用経験あり）
- AWS — 4年（ソリューションアーキテクト取得）

## プロジェクト実績の書き方

エンジニアの職務経歴書では、**プロジェクト単位**で実績を記載します。

### プロジェクト記載のフォーマット

**プロジェクト名：** ECサイトリニューアル
**期間：** 2024年4月〜2025年3月（12ヶ月）
**チーム規模：** 8名（PO1名、デザイナー1名、エンジニア6名）
**役割：** テックリード
**技術スタック：** React, TypeScript, Next.js, Node.js, PostgreSQL, AWS (ECS, RDS, S3)
**担当業務：**
- フロントエンドアーキテクチャの設計と技術選定
- API設計（OpenAPI仕様）とバックエンド実装
- CI/CDパイプラインの構築（GitHub Actions）
- コードレビュー、技術メンタリング

**成果：**
- ページ読み込み速度を3.2秒から0.8秒に改善（**75%短縮**）
- コンバージョン率が15%向上し、月間売上3,000万円増加
- デプロイ頻度を月1回から週3回に向上

## GitHub・ポートフォリオの活用

### GitHub

- プロフィールREADMEを充実させる
- ピン留めリポジトリは最も見せたいプロジェクトを選ぶ
- READMEに技術選定の理由、アーキテクチャ図、デモURLを記載
- コミットメッセージは英語で丁寧に

### ポートフォリオサイト

- Next.js + Vercelなどでポートフォリオサイトを構築
- プロジェクトの概要、技術スタック、スクリーンショット、学びを記載
- URLを履歴書のヘッダーに記載

---

## SES/SIer vs Web系の書き方の違い

### SES/SIer向け（スキルシート重視）

- 案件単位の詳細な実績
- 技術スキルのマトリクス表
- 資格（基本情報、応用情報等）の強調

### Web系向け（職務経歴書+ポートフォリオ）

- プロダクト志向の実績記載
- 技術選定の理由や設計判断の説明
- GitHub、ブログ、登壇実績

## まとめ

ITエンジニアの履歴書は、技術スキルのカテゴリ分け、プロジェクト単位の成果記載、GitHub/ポートフォリオへのリンクが3本柱です。「何をしたか」だけでなく「なぜその技術を選んだか」「どう改善したか」まで書けると、技術力だけでなく設計思考も伝わります。
